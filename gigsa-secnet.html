01

정보보안 3요소

보안

모든 보안의 출발점. 두문자 기·무·가로 외우고, 단답으로 자주 나옵니다.

CIA

기밀성 · 무결성 · 가용성

★★★
기밀성Confidentiality — 인가된 사용자만 정보에 접근 가능 (노출 방지)
무결성Integrity — 인가된 사용자만 정보를 수정 가능 (변조 방지)
가용성Availability — 인가된 사용자가 필요할 때 언제든 접근 가능
🔑 기·무·가 (기밀성·무결성·가용성). 추가로 부인방지(Non-repudiation), 인증(Authentication)도 함께 외우면 좋습니다.
RISK

보안 요소 확장 — 5요소 + 위험 관리 용어

★★☆

위 표의 3요소에 인증·부인방지를 더해 정보보안 5요소로 출제됩니다. 시험은 "설명 문장을 주고 요소 이름을 쓰라"는 매칭형으로 구별시키므로 요소마다 핵심 동사 하나로 기억하세요 — 인증은 "확인한다", 부인방지는 "부인 못 하게 한다". 특히 부인방지는 전자서명과 묶여 나오는 단답 단골입니다.

인증Authentication — 접근하는 사용자·메시지가 진짜 본인·원본이 맞는지 확인. 전형 시나리오: 로그인 시 ID와 비밀번호 검증
부인방지Non-repudiation — 송수신 사실을 사후에 부인하지 못하도록 증거를 확보. 전형 시나리오: 전자서명으로 "내가 보낸 적 없다"는 주장 차단

위험 관리 용어 4개는 관계식으로 묶어야 안 헷갈립니다. 위험(Risk)은 자산·위협·취약점의 함수 — 위협이 취약점을 통해 자산을 때릴 때 위험이 생기므로, 셋 중 하나라도 없으면 위험도 없습니다.

자산Asset — 조직이 보호해야 할 가치 있는 대상 (서버·데이터·소프트웨어·인력)
위협Threat — 자산에 손실을 일으킬 수 있는 잠재적 사건·행위자 (해커, 악성코드, 화재)
취약점Vulnerability — 위협이 파고들 수 있는 자산이 가진 약점 (패치 안 된 서버, 허술한 비밀번호 정책)
위험Risk — 위협이 취약점을 이용해 자산에 손실을 입힐 가능성

식별된 위험은 4가지 전략 중 하나로 처리합니다. 각 전략을 대표 예시와 짝지어 두세요.

회피Avoidance — 위험을 낳는 활동·자산 자체를 중단·제거. 예: 위험한 서비스 폐기
전가Transfer — 손실 부담을 제3자에게 이전. 대표 예가 보험 가입, 아웃소싱
감소Mitigation(완화) — 보안 대책을 구현해 위험을 수용 가능한 수준까지 낮춤. 예: 방화벽·백업 도입
수용Acceptance — 대책 비용이 손실보다 크다고 판단되면 위험을 감수하기로 결정하고 운영
⚠ 위협 vs 취약점 혼동 주의: 손실을 일으키는 쪽(해커·악성코드·화재)이 위협, 뚫리는 약점(미패치 서버·허술한 정책)이 취약점입니다. 설명에 "약점·결함"이 보이면 취약점, "사건·행위자"가 보이면 위협.
🔑 외우기 팁: 위험 처리 4전략은 회·전·감·수(회피·전가·감소·수용) — "회전하며 감수한다". 전가 하면 반사적으로 "보험"이 나와야 합니다.
📝 실기 이렇게 나온다: "메시지의 송수신 사실을 사후에 부인할 수 없도록 증거를 제공하는 정보보안 요소는?" → 답: 부인방지(Non-repudiation) (전자서명이 이를 보장하는 대표 기술)
📝 실기 이렇게 나온다: "위험 처리 전략 중, 보험 가입처럼 위험에 따른 손실 부담을 제3자에게 넘기는 전략은?" → 답: 위험 전가(Risk Transfer) (회피=활동 중단, 감소=대책 구현, 수용=감수 결정)
02

암호화 — 대칭 vs 비대칭

보안

거의 매회 출제. 키 개수와 알고리즘 이름을 짝지어 외우는 게 핵심입니다.

CRYPTO

대칭키 vs 비대칭키

★★★
대칭키암호화·복호화에 같은 키 사용. 빠르지만 키 분배 어려움.
예: DES, AES(키 128/192/256비트), SEED·ARIA(국산 블록암호, 기본 128비트), RC4(스트림)
비대칭키공개키로 암호화, 개인키로 복호화 (키 2개). 느리지만 키 분배 쉬움.
암·복호화 예: RSA, ECC  |  키 교환(키 분배): 디피-헬만(Diffie-Hellman) — 공개키 기반 키 교환 알고리즘(암·복호화 알고리즘이 아님)
해시단방향 암호화 (복호화 불가). 무결성 검증용.
예: SHA, MD5, HAS-160
⚠ 핵심 함정: 비대칭키는 공개키로 암호화 → 개인키로 복호화가 기본(기밀성). 반대로 개인키로 서명 → 공개키로 검증은 전자서명(부인방지). 방향을 정확히.
🔑 대칭 = 다·에·시·아(DES·AES·SEED·ARIA) / 비대칭 = RSA·ECC / 해시 = SHA·MD5.
ALGO

암호 알고리즘 지도 — 국산·경량·수학 근거

★★★

위 표가 "대칭이냐 비대칭이냐"라면, 여기는 이름을 특정하게 만드는 세부 스펙.

실기는 알고리즘을 길게 설명하지 않습니다. 국산 여부 · 블록/키 크기 · 경량(IoT) 대상 · 근거 수학 문제 같은 시그널 두어 개를 나열하고 이름을 쓰게 하죠. 아래 굵은 시그널만 잡으면 답이 하나로 좁혀집니다.

DES블록 64비트 · 키는 64비트 중 패리티 8비트를 뺀 유효 56비트. 현재는 취약 — 3DES(DES 3회 적용)를 거쳐 AES로 대체
AESDES를 대체한 미국(NIST) 표준. 블록 128비트 고정, 키 128/192/256비트. 시나리오: HTTPS·디스크 암호화 등 현대 대칭키의 사실상 표준
SEED국산(KISA 개발) 블록 암호. 블록·키 모두 128비트. 국내 금융·전자상거래에서 오래 사용
ARIA국산 · 국가 표준(KS). 경량 환경·하드웨어 구현 효율에 최적화. 블록 128비트, 키 128/192/256(AES와 동일 규격). 이름은 학계·연구소·정부(Academy·Research Institute·Agency) 합작의 약자
LEA국산 경량 고속(Lightweight Encryption Algorithm). 블록 128비트. 모바일·IoT·빅데이터 등 고속 경량 환경용
HIGHT국산 초경량. 블록 64비트·키 128비트. RFID·USN 등 저전력 장비를 위해 개발
IDEA블록 64비트·키 128비트. 이메일 암호화 PGP에 채택된 것으로 유명

스트림 암호는 비트·바이트 단위로 키 스트림과 XOR하는 방식입니다. 대표가 RC4(WEP·초기 SSL에 사용, 현재는 취약)이고, LFSR(선형 피드백 시프트 레지스터)은 키 스트림을 만들어내는 기본 부품으로 출제됩니다.

RSA근거: 큰 수의 소인수분해가 어렵다는 문제. 암호화·전자서명 모두 가능한 범용 공개키
ECC근거: 타원곡선 이산대수 문제. RSA보다 훨씬 짧은 키로 동등한 보안 강도 → 모바일·IoT에 유리
디피-헬만근거: 이산대수 문제. 키 교환 전용(최초의 공개키 개념) — 자체 암호화·서명 기능은 없고, 인증 없이 쓰면 중간자 공격에 취약
ElGamal근거: 이산대수 문제. 난수를 써서 같은 평문도 매번 다른 암호문이 되고, 암호문 길이가 2배로 커지는 단점

실무 시나리오 한 줄: HTTPS(TLS)는 (타원곡선) 디피-헬만으로 세션 키를 합의하고 본문은 AES로 암호화 — 비대칭(키 분배) + 대칭(속도)을 결합한 하이브리드 방식.

⚠ 함정: "DES의 키 길이"는 묻는 방식에 따라 답이 다릅니다. 전체 키는 64비트지만 8비트는 패리티(오류 검출)용이라 유효 키 길이는 56비트. "실제 암호화에 쓰이는(유효) 키"를 물으면 56이 답입니다.
🔑 외우기 팁: 국산 4형제 = SEED(원조·금융) / ARIA(국가 표준) / LEA(경량 고속) / HIGHT(초경량 IoT) — 국산 중 블록이 64비트인 건 HIGHT뿐. 수학 근거는 "RSA만 소인수분해, ECC는 '타원곡선'이 붙은 이산대수, DH·ElGamal은 이산대수".
📝 실기 이렇게 나온다: "경량 환경 및 하드웨어 구현 효율성을 위해 개발된 국산 128비트 블록 암호로, 국가 표준으로 제정된 알고리즘은?" → 답: ARIA ("국가 표준"이 결정적 시그널 — SEED와 구별)
📝 실기 이렇게 나온다: "타원곡선 수학 구조를 이용해 RSA보다 짧은 키로 동등한 수준의 보안을 제공하는 공개키 암호 방식은?" → 답: ECC(타원곡선 암호) ("짧은 키"가 시그널)
HASH

해시 심화 — 솔트 · 레인보우 테이블 · 키 스트레칭

★★☆

해시는 임의 길이 입력을 고정 길이 다이제스트로 압축하는 일방향 함수입니다. 실기는 두 각도로 구별시킵니다 — ① 해시의 성질과 다이제스트 비트 수(MD5는 몇 비트?) ② 비밀번호 저장을 지키는 기법 이름(설명→솔트/키 스트레칭). 특히 ②는 서술형 소재로도 좋아 정의를 문장으로 써 볼 것.

고정 길이 출력입력이 1글자든 1GB든 다이제스트 길이는 항상 동일
일방향성다이제스트에서 원문을 복원할 수 없음 — 복호화 과정 자체가 존재하지 않음
충돌 저항성같은 다이제스트를 갖는 서로 다른 두 입력을 찾기 어려워야 함 (충돌 회피)
MD5다이제스트 128비트. 충돌이 실제로 발견돼 보안 용도로는 취약
SHA-1다이제스트 160비트. 역시 충돌 발견 → 취약, 퇴출 수순
SHA-2SHA-256/384/512 등 — 이름의 숫자가 곧 다이제스트 비트 수. 현재 표준

비밀번호를 해시로 저장해도 미리 계산해 둔 표로 역추적당할 수 있습니다. 그래서 공격(레인보우 테이블) ↔ 방어(솔트·키 스트레칭)를 한 세트로 외웁니다.

레인보우
테이블평문→해시 쌍을 사전에 대량 계산해 둔 역추적용 표. 훔친 해시값을 표에서 찾아 원래 비밀번호를 알아냄
솔트Salt — 해싱 전에 비밀번호에 사용자별 랜덤 값을 첨가. 같은 비밀번호라도 저장 해시가 달라져 레인보우 테이블 무력화
키 스트레칭해시를 수천~수만 회 반복 적용해 검증 1회를 일부러 느리게 → 무차별 대입 비용 폭증. 구현: PBKDF2 · bcrypt · scrypt

시나리오 한 줄: alice와 bob이 똑같이 "1234"를 써도 솔트가 다르면 저장된 해시가 서로 달라, 공격자는 표를 사용자마다 새로 계산해야 합니다.

⚠ 함정: 해시는 복호화 과정이 없는 일방향 방식입니다 — "키로 복호화해 원문을 얻는다"는 서술이 있으면 해시가 아닙니다. 그리고 솔트는 비밀 키가 아니어서 해시와 나란히 저장해도 됩니다 — 목적은 은닉이 아니라 "사전 계산(레인보우 테이블) 무력화"이기 때문.
🔑 외우기 팁: 공격은 표(레인보우 테이블), 표를 깨는 건 소금(솔트), 시간을 끄는 건 반복(키 스트레칭).
📝 실기 이렇게 나온다: "비밀번호를 해시로 저장할 때 사용자마다 다른 임의의 값을 덧붙여, 동일한 비밀번호라도 서로 다른 해시가 생성되게 하는 기법은?" → 답: 솔트(Salt) (레인보우 테이블 공격 무력화가 목적)
📝 실기 이렇게 나온다: "해시 함수를 수만 회 반복 적용해 무차별 대입 공격 속도를 늦추는 기법으로 PBKDF2, bcrypt, scrypt가 대표적인 이것은?" → 답: 키 스트레칭(Key Stretching)
03

공격기법 — 웹 취약점

보안

약술 최대 빈출. 각 공격의 핵심 동작 한 문장을 정확히 쓸 수 있어야 합니다.

ATTACK

주요 웹 공격기법

★★★
SQL 인젝션입력값에 악의적 SQL을 삽입해 DB를 비정상 조회·조작하는 공격. (방어: Prepared Statement)
XSS웹 페이지에 악성 스크립트를 삽입해 쿠키·세션 등 개인정보를 탈취. (Cross-Site Scripting)
CSRF사용자가 자신도 모르게 공격자가 의도한 요청을 보내게 하는 공격. (Cross-Site Request Forgery)
명령어 삽입검증 안 된 입력값이 OS 명령어로 실행되도록 하는 공격 (Command Injection)
⚠ XSS vs CSRF 구분: XSS는 스크립트 실행으로 정보 탈취, CSRF는 위조된 요청으로 행위 유발. 둘 다 빈출이니 차이를 명확히.
DOS

서비스 거부 · 네트워크 공격

★★☆
DoS대량 트래픽으로 시스템을 마비시켜 정상 서비스를 방해
DDoS여러 좀비 PC를 동원한 분산 서비스 거부 공격
스니핑네트워크 패킷을 몰래 가로채 정보를 훔쳐봄 (수동적)
스푸핑IP·MAC 등을 위조해 신뢰된 대상으로 가장 (능동적)
💡 스니핑 vs 스푸핑: 스니핑은 "엿보기"(가로채기), 스푸핑은 "위장"(속이기). 헷갈리기 쉬우니 동사로 구분.
04

접근통제 · 인증

보안

접근통제 모델 3종과 인증 방식이 단답으로 출제됩니다.

AC

접근통제 모델 (DAC/MAC/RBAC)

★★☆
DAC임의적 접근통제 — 자원 소유자가 권한 부여 (Discretionary)
MAC강제적 접근통제 — 보안 등급에 따라 시스템이 강제 (Mandatory)
RBAC역할 기반 접근통제 — 역할(직책)에 따라 권한 부여 (Role-Based)
🔐 인증 방식: SSO=한 번 인증으로 여러 시스템 접근 / OTP=일회용 비밀번호 / 커버로스(Kerberos)=티켓 기반 인증.
SIGN

전자서명 · PKI

★★☆
전자서명개인키로 서명 → 공개키로 검증. 인증·무결성·부인방지를 보장 (기밀성은 보장하지 않음).
PKI공개키 기반구조(Public Key Infrastructure). 공개키·인증서를 신뢰성 있게 관리하는 체계.
CA인증기관(Certificate Authority). 공개키의 소유자를 보증하는 인증서를 발급·관리.
⚠ 함정: 전자서명은 기밀성을 제공하지 않습니다. 기밀성(암호화)은 수신자의 공개키로 별도 암호화해야 보장됩니다.
AUTH

인증 4유형 + AAA · SSO · 커버로스 · OAuth

★★☆

인증 수단은 4가지 유형으로 분류되고, 시험은 "OTP는 무슨 기반 인증인가"처럼 수단→유형 매칭으로 구별시킵니다. 이어서 AAA·커버로스·OAuth는 "설명→용어" 단답감 — 각각 3요소 / 티켓·KDC / 토큰 위임이라는 시그널로 판별합니다.

지식 기반Something you know — 머릿속에만 있는 것. 비밀번호 · PIN · 보안 질문
소유 기반Something you have — 갖고 있는 물건. OTP 토큰 · 스마트카드 · 인증서 · 휴대폰
생체 기반Something you are(존재 기반) — 몸 그 자체. 지문 · 홍채 · 정맥 · 얼굴
행위 기반Something you do — 행동의 패턴. 서명 · 키스트로크(타이핑 리듬) · 걸음걸이

2요소 인증(2FA)은 서로 다른 유형 2가지 이상의 조합입니다. 비밀번호+OTP는 지식+소유라 2요소가 맞습니다.

AAA인증(Authentication, 누구인가) → 인가(Authorization, 무엇이 허용되나) → 계정관리(Accounting, 무엇을 했는지 기록·과금). 대표 프로토콜: RADIUS, DIAMETER
SSOSingle Sign-On — 한 번의 인증으로 연동된 여러 시스템에 재로그인 없이 접근. 편의성이 크지만 계정 하나가 뚫리면 전체가 위험해 강한 인증과 병행
커버로스Kerberos — 대칭키 기반 티켓 인증 프로토콜. KDC(키 분배 센터)가 발급한 TGT·티켓으로 각 서버에 인증하므로 비밀번호를 매번 전송하지 않음. 시나리오: 윈도우 AD 도메인 로그인
OAuth비밀번호를 제3자 앱에 알려주지 않고 액세스 토큰으로 권한을 위임하는 개방형 표준. 시나리오: "구글 계정으로 로그인"(단, 소셜 로그인의 인증 자체는 OAuth 위에 얹은 OIDC가 담당 — OAuth는 권한 위임)

커버로스 동작 한 줄: 로그인 → AS(인증 서버)가 TGT 발급 → TGS(티켓 발급 서버)에 TGT를 내고 서비스 티켓 수령 → 서버에 티켓 제시. KDC = AS + TGS.

⚠ 인증 vs 인가: Authentication은 신원 확인("너 누구야"), Authorization은 권한 부여("뭘 해도 되나") — 인증이 먼저, 인가가 다음입니다. 한 글자 차이로 채점이 갈립니다.
⚠ 2요소 함정: 비밀번호+PIN은 둘 다 지식 기반이라 2요소 인증이 아닙니다. "서로 다른 유형"이 정의의 핵심.
📝 실기 이렇게 나온다: "시스템 접근 통제를 위해 인증(Authentication) · 인가(Authorization) · 계정관리(Accounting)를 제공하는 정보보호 프레임워크는?" → 답: AAA (구현 프로토콜로 RADIUS·DIAMETER)
📝 실기 이렇게 나온다: "KDC가 발급하는 티켓(TGT)을 기반으로 사용자를 인증하는 대칭키 기반의 중앙집중식 인증 프로토콜은?" → 답: 커버로스(Kerberos) ("티켓·KDC"가 결정적 시그널)
MODEL

접근통제 보안 모델 — BLP · Biba · 클락-윌슨

★★☆

위의 DAC·MAC·RBAC가 "누가 권한을 주나"의 분류라면, 보안 모델은 그 규칙을 정형화한 이론.

시험은 모델 설명을 주고 이름을 쓰게 하며, 구별 축은 딱 두 개입니다 — ① 지키려는 것이 기밀성이냐 무결성이냐 ② No Read/Write의 방향이 위냐 아래냐. 이 두 축만 잡으면 4개 모델이 전부 갈라집니다.

벨-라파둘라BLP — 기밀성 모델(군사 기밀 등급에서 출발한 최초의 수학적 보안 모델). No Read Up + No Write Down. MAC 계열
비바Biba — 무결성 모델. No Read Down + No Write Up — BLP와 방향이 정반대. 신뢰도 낮은 데이터가 위로 스미는 것을 차단
클락-윌슨Clark-Wilson — 무결성 모델(상업 환경). 데이터에 직접 접근 금지, 반드시 잘 구성된 트랜잭션(검증된 프로그램)을 통해서만 + 직무 분리. 시나리오: 은행 계좌는 이체 프로그램으로만 수정 가능
만리장성Chinese Wall(브루어-나쉬) — 이해 충돌 방지. A사 자료에 접근한 컨설턴트는 경쟁사 B 자료 접근이 차단 — 접근 이력에 따라 동적으로 권한 결정

네 규칙은 방향까지 정확히 — 어느 모델의 규칙인지 뒤집어 내는 게 전형 함정입니다.

No Read UpBLP — 자기보다 높은 기밀 등급을 읽기 금지 (기밀 열람 차단)
No Write DownBLP — 자기보다 낮은 등급에 쓰기 금지 (기밀이 아래로 새는 것 차단)
No Read DownBiba — 무결성 낮은 데이터 읽기 금지 (오염된 정보 수혈 방지)
No Write UpBiba — 무결성 높은 데이터에 쓰기 금지 (신뢰 데이터 훼손 방지)

시나리오 한 줄: "2급 인가자는 1급 문서를 열람할 수 없고, 자기 2급 보고서를 3급 게시판에 올릴 수 없다" — 이 문장이 보이면 BLP.

⚠ 함정: BLP=기밀성, Biba=무결성이고 Read/Write 금지 방향이 서로 정반대입니다. "No Read Up"이 보이면 BLP, "No Read Down"이 보이면 Biba — Up/Down 한 단어를 바꿔치기해 출제합니다.
🔑 외우기 팁: Biba의 i = Integrity(무결성). 무결성 모델이 두 개 나오면 — 등급 규칙이면 비바, "트랜잭션·직무 분리"가 보이면 클락-윌슨.
📝 실기 이렇게 나온다: "군사 보안 등급에서 출발한 기밀성 중심 모델로, 자신보다 높은 등급의 정보를 읽을 수 없고(No Read Up) 낮은 등급으로 쓸 수 없는(No Write Down) 접근통제 모델은?" → 답: 벨-라파둘라(BLP) 모델
📝 실기 이렇게 나온다: "데이터 무결성을 위해 낮은 등급의 데이터를 읽을 수 없고 높은 등급의 객체에 쓸 수 없도록 한, BLP와 규칙 방향이 반대인 모델은?" → 답: 비바(Biba) 모델
05

보안 솔루션

보안

방화벽·IDS·IPS·VPN은 약어와 핵심 역할을 정확히 매칭해야 합니다. 특히 IDS vs IPS, AH vs ESP가 빈출.

FW/IDS

방화벽 · IDS · IPS

★★★
방화벽내·외부 네트워크 사이에서 정책에 따라 패킷을 허용/차단. 발전 순서: 패킷 필터링 → 스테이트풀(상태 추적) → 애플리케이션 게이트웨이(프록시)
IDS침입 탐지 시스템(Intrusion Detection System). 비정상 행위를 탐지·경고만 함 (오용 탐지 / 이상 탐지)
IPS침입 방지 시스템(Intrusion Prevention System). 탐지 + 능동적 차단까지 수행
💡 IDS vs IPS: IDS=탐지만(수동), IPS=탐지+차단(능동). 방화벽은 정책 기반 허용/차단이 핵심.
VPN

VPN · IPSec

★★☆
VPN가상사설망(Virtual Private Network). 공중망에 암호화된 터널을 만들어 사설망처럼 안전하게 통신
AHIPSec의 인증 헤더(Authentication Header). 무결성·인증 제공 (기밀성 X)
ESPIPSec의 보안 페이로드(Encapsulating Security Payload). 기밀성 + 무결성·인증 제공
동작 모드전송 모드=페이로드만 보호(종단 간) / 터널 모드=IP 헤더 포함 전체 보호(게이트웨이 간)
⚠ AH vs ESP: AH는 기밀성을 제공하지 않습니다(암호화 X). 기밀성이 필요하면 ESP를 사용.
SOLUTION

보안 솔루션 총정리 — 시그널 키워드 사전

★★★

솔루션명 단답은 정의 전체가 아니라 설명 속 시그널 단어 한두 개로 판별합니다 — "웹 공격 특화"면 WAF, "접속 시 검사·격리"면 NAC, "유출 방지"면 DLP, "빅데이터 상관 분석"이면 SIEM. 아래 표의 굵은 글씨가 그 시그널입니다.

① 막는 쪽 — 트래픽·데이터를 통제하는 솔루션.

WAF웹 방화벽(Web Application Firewall) — SQL 인젝션·XSS 등 웹 공격에 특화. 일반 방화벽이 못 보는 HTTP 요청 내용을 검사
NACNetwork Access Control — 단말이 내부망에 접속하는 시점에 백신·패치 등 보안 정책 준수를 검사, 미달 단말은 격리(검역)
DLPData Loss Prevention — 이메일·USB·인쇄 등 유출 경로를 감시해 내부 정보의 외부 유출을 차단. 시나리오: 설계도면의 USB 복사 차단
DRMDigital Rights Management — 문서·콘텐츠를 암호화하고 열람·인쇄·복사 권한을 통제 (디지털 저작권·기밀문서 보호)

② 보는 쪽 — 탐지·관제·분석 솔루션.

ESMEnterprise Security Management — 방화벽·IDS 등 여러 보안 장비의 로그를 모아 통합 관제
SIEMSecurity Information & Event Management — ESM의 진화형. 빅데이터 기반으로 로그·이벤트를 상관 분석해 숨은 위협 탐지
EDREndpoint Detection & Response — PC·서버 등 엔드포인트의 행위를 지속 수집·분석해 위협 탐지·대응
샌드박스의심 파일을 격리된 가상 환경에서 실행시켜 행위를 분석 — 시그니처 없는 신종 악성코드 탐지
허니팟일부러 취약해 보이게 만든 미끼 시스템 — 공격자를 유인해 수법을 분석하고 시간을 지연
Tripwire파일의 해시를 보관해 두고 주기적으로 비교 — 파일 무결성 점검·변조 탐지 도구. 시나리오: 침입자가 바꿔치기한 시스템 파일(백도어) 적발
⚠ 혼동 세트: ESM vs SIEM — 둘 다 "통합"이지만 빅데이터 상관 분석이 나오면 SIEM. 방화벽 vs WAF — 웹(HTTP) 특화라는 말이 있으면 WAF. DLP vs DRM — 유출 차단은 DLP, 권한(열람·인쇄) 통제는 DRM.
📝 실기 이렇게 나온다: "네트워크에 접속하려는 단말의 보안 정책 준수 여부를 검사해 접속을 통제하고, 미준수 단말을 격리하는 보안 솔루션은?" → 답: NAC ("접속 시점 검사 + 격리"가 시그널)
📝 실기 이렇게 나온다: "다양한 보안 장비의 로그·이벤트를 빅데이터 기반으로 수집하고 상관 분석하여 위협을 탐지하는 보안 관제 솔루션은?" → 답: SIEM (통합 수집만 하면 ESM, 상관 분석까지면 SIEM)
06

추가 공격기법

보안

최근 빈출 공격기법. 단답·약술로 자주 나오니 핵심 동작 한 문장으로 기억하세요.

ATTACK+

지능형·사회공학 공격

★★☆
APT지능형 지속 위협(Advanced Persistent Threat). 특정 대상을 장기간 은밀히 공격
랜섬웨어파일을 암호화한 뒤 복호화 대가로 금전을 요구하는 악성코드 (Ransomware)
피싱/스미싱피싱=가짜 사이트·메일로 정보 탈취 / 스미싱=문자(SMS)로 악성 링크 유도
제로데이제로데이(0-day) — 보안 패치가 나오기 전 취약점을 악용하는 공격
무차별 대입Brute Force — 모든 경우의 수를 대입해 비밀번호를 알아냄. 사전 공격은 사전 단어를 대입
사회공학Social Engineering — 사람의 심리·신뢰를 이용해 정보를 빼냄 (기술적 취약점 X)
💡 구분: 무차별 대입=모든 조합, 사전 공격=사전 단어 목록. 스미싱의 "S"는 SMS(문자)를 의미.
MODERN

최신 공격 용어 사전

★★★

위 표(APT·랜섬웨어·피싱 등)에 이어, 최근 단답에 자주 등장하는 용어들.

전부 "설명→용어" 단답감이고, 구별 축은 세 개입니다 — 누구를 노리나(불특정 다수/특정인/임원), 무엇을 조작하나(QR/DNS/Wi-Fi/도메인 철자), 계정 공격이면 무엇을 대입하나(모든 조합/유출 목록/흔한 비번 하나).

공급망 공격SW 개발·업데이트·유통 과정에 악성코드를 심어, 정상 업데이트를 설치한 사용자들을 일괄 감염 (Supply Chain Attack)
크리덴셜
스터핑이미 유출된 ID·비밀번호 목록을 다른 사이트에 자동 대입 — 비밀번호 재사용 습관을 노림 (Credential Stuffing)
패스워드
스프레이흔한 비밀번호 한두 개를 다수 계정에 넓게 시도 — 한 계정을 연타하지 않아 계정 잠금을 회피
스피어 피싱특정 개인·조직을 표적으로 맞춤 정보를 담아 보내는 피싱 메일 (Spear Phishing). 시나리오: 인사팀을 사칭한 "연봉계약서" 첨부
웨일링스피어 피싱 중에서도 CEO 등 고위 임원("고래")을 노리는 공격 (Whaling)
큐싱QR 코드 + 피싱(Qshing) — 가짜 QR로 악성 앱 설치나 가짜 사이트 접속 유도
파밍DNS(또는 hosts 파일)를 변조해, 사용자가 올바른 주소를 입력해도 가짜 사이트로 연결 (Pharming)
워터링 홀표적이 자주 방문하는 사이트를 미리 감염시켜 접속을 기다리는 매복형 공격 (Watering Hole)
이블 트윈정상 AP와 같은 이름(SSID)의 가짜 Wi-Fi AP를 세워 접속을 유도, 트래픽을 가로챔 (Evil Twin)
타이포스쿼팅오타 도메인(예: gogle.com)을 선점해 잘못 입력한 사용자를 가짜 사이트로 유도 — URL 하이재킹이라고도 (Typosquatting)
드라이브 바이
다운로드감염된 웹페이지 방문만으로 사용자 모르게 악성코드가 내려받아져 설치 — 브라우저·플러그인 취약점 악용 (Drive-by Download)
⚠ 계정 공격 3종 구분: 무차별 대입 = 모든 조합을 생성해 대입 / 크리덴셜 스터핑 = 유출된 진짜 계정 목록을 재사용 / 패스워드 스프레이 = 흔한 비번 하나로 여러 계정. "유출 목록"이라는 말이 있으면 크리덴셜 스터핑.
⚠ 피싱 vs 파밍: 피싱은 가짜 링크·메일로 사용자를 속여 유인, 파밍은 DNS를 속여 올바른 URL을 입력해도 끌려감. 문제에 "올바른 주소를 입력했는데도"가 보이면 파밍.
🔑 외우기 팁: 표적이 좁아지는 순서 — 피싱(불특정 다수) → 스피어 피싱(특정인) → 웨일링(임원). 창(spear)으로 겨누다 고래(whale)까지.
📝 실기 이렇게 나온다: "다른 곳에서 유출된 로그인 정보 목록을 확보해 여러 사이트에 자동으로 대입하며 로그인을 시도하는 공격은?" → 답: 크리덴셜 스터핑 ("유출 목록 재사용"이 무차별 대입과의 차이)
📝 실기 이렇게 나온다: "공격 대상이 자주 방문하는 웹사이트를 미리 감염시켜 두고 접속하기를 기다리는 표적 공격 기법은?" → 답: 워터링 홀(Watering Hole) (맹수가 물웅덩이에서 사냥감을 기다리는 데서 유래)
KILLCHAIN

사이버 킬 체인 7단계

★☆☆

록히드 마틴이 제안한 APT 공격의 7단계 모델입니다. 공격은 이 사슬을 순서대로 거치므로 한 단계만 끊어도 전체 공격이 무산된다는 것이 핵심 발상이고, 단계별 탐지·차단 체계를 세우는 데 씁니다. 시험은 단계 순서 빈칸 채우기나 단계 이름 쓰기로 구별시킵니다.

1. 정찰Reconnaissance — 표적 정보 수집. 예: 임직원 이메일·SNS·공개 서버 조사
2. 무기화Weaponization — 익스플로잇+악성코드를 전달 가능한 형태로 결합. 예: 악성 매크로를 심은 문서 파일 제작 (아직 공격자 내부의 준비 단계)
3. 전달Delivery — 무기를 표적에 운반. 예: 스피어 피싱 메일 첨부, 악성 URL, USB
4. 익스플로잇Exploitation — 도착한 무기가 취약점을 격발해 코드 실행. 예: 첨부 파일을 여는 순간 실행
5. 설치Installation — 지속 거점 확보. 예: 백도어·원격 제어 도구(RAT) 설치
6. 명령·제어Command & Control(C2) — 감염 시스템이 공격자 서버와 통신 채널을 열고 원격 조종 대기
7. 목적 달성Actions on Objectives — 최종 목표 실행. 예: 내부 이동 후 데이터 유출·파괴·암호화

방어 관점: 뒤로 갈수록 피해가 커지므로 앞 단계에서 끊을수록 이득입니다.

  • 전달 차단 — 스팸 필터, 첨부 파일 샌드박스 분석
  • 익스플로잇·설치 차단 — 보안 패치, 백신·EDR
  • C2 차단 — 비정상 아웃바운드 트래픽 탐지·차단으로 원격 조종 끊기

함께 나오는 용어: MITRE ATT&CK — 킬 체인이 "단계 모델"이라면, ATT&CK은 실제 공격에서 관찰된 전술(Tactics)·기법(Techniques)을 정리한 지식 베이스(매트릭스).

⚠ 순서 함정: 무기화는 표적에게 아무것도 보내기 전인 공격자 내부 준비 단계라 전달보다 앞입니다. 그리고 전달(도착) 뒤에 익스플로잇(격발) — "도착 후 폭발" 순서를 뒤집어 출제합니다.
🔑 외우기 팁: 정찰 → 무기화 → 전달 → 익스플로잇 → 설치 → C2 → 목적 달성. 동사 7개로 — "살피고, 만들고, 보내고, 터뜨리고, 심고, 조종하고, 훔친다".
📝 실기 이렇게 나온다: "사이버 킬 체인의 빈칸을 채우시오: 정찰 → ( ① ) → 전달 → 익스플로잇 → 설치 → ( ② ) → 목적 달성" → 답: ① 무기화(Weaponization), ② 명령·제어(C2, Command & Control)

DHCP

DHCP · DNS · ARP 동작 원리

★★☆

IP를 자동으로 받고, 이름을 주소로, 주소를 물리주소로 바꾸는 흐름 — 그 순서가 그대로 문제가 됩니다.

DHCP는 IP를 자동 할당하며, 4단계 흐름 DORA가 단골입니다. Discover(클라이언트가 브로드캐스트로 서버 탐색) → Offer(서버가 IP 제안) → Request(클라이언트가 그 IP 요청) → Ack(서버가 확정). 포트는 서버 UDP 67, 클라이언트 UDP 68로 고정.

DNS 레코드는 종류별 역할을 매칭하는 형태로 나옵니다.

A / AAAAA=도메인→IPv4 주소 / AAAA=도메인→IPv6 주소(쿼드A)
CNAME한 도메인을 다른 도메인 이름에 연결하는 별칭(alias)
MX메일 서버(Mail eXchanger)를 지정
NS해당 도메인을 관리하는 네임서버를 지정
PTRIP→도메인 역방향(reverse) 조회용

주소 변환·제어 — ARP=IP→MAC(브로드캐스트로 “이 IP의 MAC 알려줘” 질의) / RARP=MAC→IP(반대). ICMP는 오류·제어 메시지 프로토콜로 타입 번호가 포인트입니다.

ICMP 8/08=Echo Request, 0=Echo Reply → ping이 사용
ICMP 11Time Exceeded(TTL 만료) → traceroute 원리
ICMP 3Destination Unreachable(목적지 도달 불가)
⚠ ARP vs RARP 방향: ARP는 IP→MAC(논리→물리), RARP는 MAC→IP. 화살표를 반대로 쓰면 오답. DHCP 포트도 서버=67·클라이언트=68로 짝을 고정하세요.
🔑 두문자: DHCP 4단계 = DORA(Discover·Offer·Request·Ack).
📝 실기 이렇게 나온다: “클라이언트가 IP 주소를 자동으로 할당받는 DHCP의 4단계 과정을 순서대로 쓰시오.” → 답: Discover → Offer → Request → Ack (DORA)
📝 실기 이렇게 나온다: “traceroute가 경로를 추적할 때 이용하는, TTL이 0이 되어 패킷이 폐기될 때 발생하는 ICMP 메시지는?” → 답: Time Exceeded(Type 11)
DEVICE

계층별 장비 · PDU 총정리

★★★

“이 장비는 몇 계층?”, “이 계층의 전송 단위는?” — 매칭형으로 거의 매회 출제됩니다.

장비는 동작하는 계층 = 읽는 주소로 구별합니다. 아래로 갈수록 상위 계층을 처리합니다.

1계층리피터·허브 — 비트. 신호 증폭·재생, 모든 포트로 전달(충돌 도메인 1개)
2계층브리지·스위치 — 프레임. MAC 주소 학습, 포트별 충돌 도메인 분리
3계층라우터·L3 스위치 — 패킷. IP 라우팅, 브로드캐스트 도메인 분리
4계층L4 스위치 — 세그먼트. 포트 번호 기반 로드밸런싱
7계층게이트웨이·L7 — 데이터. 콘텐츠 기반 스위칭·프로토콜 변환

PDU(전송 단위) 아래→위: 비트 → 프레임 → 패킷 → 세그먼트 → 데이터(메시지). 캡슐화하며 계층마다 헤더가 붙습니다.

⚠ 허브 vs 스위치: 허브는 모든 포트가 하나의 충돌 도메인(대역폭 공유)이지만 스위치는 포트마다 충돌 도메인을 분리. 단, 브로드캐스트 도메인을 나누는 것은 스위치가 아니라 라우터(3계층)입니다.
🔑 외우기 팁: PDU 순서(1→7계층) = 비·프·패·세·데(비트·프레임·패킷·세그먼트·데이터).
📝 실기 이렇게 나온다: “리피터·허브가 1계층, 브리지·스위치가 2계층 장비라면 라우터는 몇 계층 장비인가?” → 답: 3계층(네트워크 계층)
📝 실기 이렇게 나온다: “데이터링크 계층에서 데이터의 전송 단위(PDU)를 무엇이라 하는가?” → 답: 프레임(Frame)

SUBNET

서브네팅 계산 완전 정복

★★☆

약술이 아니라 “계산”으로 나오는 유일한 네트워크 파트. 절차만 외우면 항상 맞힙니다.

계산 3단계 — 필요 개수로 빌릴 비트를 정하고, 블록 크기로 경계를 끊습니다.

  • ① 차용 비트 — 서브넷 N개 필요 시 2^m ≥ N인 최소 m비트를 호스트부에서 빌려 프리픽스에 더한다
  • ② 블록 크기 — 256 − (해당 옥텟의 마스크값) = 서브넷 사이 간격
  • ③ 범위 — 각 블록의 첫 주소=네트워크, 마지막=브로드캐스트, 그 사이가 호스트

예제 1 — 192.168.10.0/24를 4개 서브넷으로: 4개=2^2 → 2비트 차용 → /24+2=/26. 4옥텟 마스크 192 → 블록 크기 256−192=64. 서브넷당 호스트 = 2^(32−26)−2 = 62개.

서브넷 1네트워크 192.168.10.0 · 브로드캐스트 .63 · 호스트 .1~.62 (62개)
서브넷 2네트워크 .64 · 브로드캐스트 .127 · 호스트 .65~.126
서브넷 3네트워크 .128 · 브로드캐스트 .191 · 호스트 .129~.190
서브넷 4네트워크 .192 · 브로드캐스트 .255 · 호스트 .193~.254

예제 2 — 호스트 500대 필요: 2^8−2=254(부족), 2^9−2=510 ≥ 500 → 호스트 비트 9 → 프리픽스 32−9=/23.

🔑 공식: 서브넷당 호스트 = 2^(호스트비트)−2 (네트워크·브로드캐스트 주소 2개 제외) / 서브넷 수 = 2^(차용비트).
⚠ −2 함정: 사용 가능 호스트는 네트워크 주소와 브로드캐스트 주소 2개를 반드시 뺀다. /26이면 64개가 아니라 62개. 이 −2를 빠뜨리는 것이 최다 감점 실수입니다.
📝 실기 이렇게 나온다: “C클래스 네트워크를 /27로 서브네팅할 때 한 서브넷에서 실제 사용 가능한 호스트 수를 쓰시오.” → 답: 30개 (2^5−2=30)
📝 실기 이렇게 나온다: “한 부서에 호스트 100대를 수용하려면 최소 서브넷 마스크(프리픽스)는?” → 답: /25 (2^7−2=126 ≥ 100, 마스크 255.255.255.128)
ROUTE

라우팅 프로토콜 심화 — RIP vs OSPF vs BGP

★★☆

AS(자율 시스템) 안이냐 밖이냐로 크게 갈리고, 그 안에서 알고리즘·메트릭으로 세분됩니다.

분류 — AS 내부=IGP(RIP·OSPF), AS 간=EGP(BGP). 세 프로토콜은 아래 시그널로 구별합니다.

RIP거리 벡터(벨만-포드), 메트릭=홉 수, 최대 15홉(16=도달 불가), 30초 주기 갱신, 소규모
OSPF링크 상태(다익스트라·SPF), 메트릭=비용(cost), 에어리어 분할, 빠른 수렴, 대규모
BGP경로 벡터, AS 간(EGP), TCP 179, 인터넷 백본의 표준

정적 vs 동적 — 정적 라우팅=관리자가 경로를 수동 설정(소규모·안정적, 장애 자동 대응 X) / 동적 라우팅=프로토콜이 경로를 자동 학습·갱신(대규모·장애 시 자동 우회).

⚠ RIP 15홉 함정: RIP는 홉 수 최대 15까지만 유효하고 16홉은 무한대(∞)=도달 불가로 처리합니다. “16홉까지 가능”은 오답. IGP/EGP 분류에서 BGP만 EGP인 점도 단골입니다.
🔑 외우기 팁: 거리벡터=RIP=벨만포드 / 링크상태=OSPF=다익스트라. OSPF의 SPF(Shortest Path First)를 다익스트라와 묶어 기억하세요.
📝 실기 이렇게 나온다: “거리 벡터 방식으로 홉 수를 메트릭으로 사용하며 최대 15홉으로 제한되는 라우팅 프로토콜은?” → 답: RIP
📝 실기 이렇게 나온다: “링크 상태 알고리즘(다익스트라)을 사용하고 에어리어로 분할해 대규모 망에서 빠르게 수렴하는 IGP는?” → 답: OSPF
IPv6

IPv6 상세 · IPv4 전환 · NAT

★★☆

IPv4 주소 고갈의 해법 3종 세트 — 더 긴 주소(IPv6), 전환 기술, 주소 재사용(NAT).

IPv6는 128비트를 콜론(:)으로 나눈 16진수 4자리 8그룹으로 표기합니다. 주소 유형은 3종 — 유니캐스트(1:1), 멀티캐스트(1:그룹), 애니캐스트(가장 가까운 하나). 이 밖에 헤더 단순화(고정 길이 기본 헤더), IPSec 기본 지원, 주소 자동 구성이 특징입니다.

IPv4 → IPv6 전환 3기술과 NAT 3방식을 각각 구별하세요.

듀얼 스택IPv4·IPv6 프로토콜을 동시에 구동 (전환 기술)
터널링IPv6 패킷을 IPv4로 캡슐화해 IPv4 망을 통과 (전환 기술)
주소 변환IPv6↔IPv4 헤더/주소를 변환(NAT-PT 등, 전환 기술)
정적 NAT사설↔공인 IP를 1:1 고정 매핑
동적 NAT공인 IP 풀에서 가용 주소를 동적으로 할당(N:M)
PAT(NAPT)한 공인 IP를 포트로 구분해 다수가 공유(1:N) — 가정용 공유기
⚠ IPv6 브로드캐스트 함정: IPv6에는 브로드캐스트가 없습니다. 유니캐스트·멀티캐스트·애니캐스트 3종뿐이며, 브로드캐스트 역할은 멀티캐스트가 대신합니다.
📝 실기 이렇게 나온다: “IPv6의 주소 지정 방식(유형) 3가지를 쓰시오.” → 답: 유니캐스트, 멀티캐스트, 애니캐스트 (브로드캐스트 없음)
📝 실기 이렇게 나온다: “하나의 공인 IP를 여러 사설 IP가 포트 번호로 구분하여 공유하는 NAT 방식은?” → 답: PAT(NAPT)
