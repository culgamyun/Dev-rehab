Chapter R1: 로보틱스 입문 & 선형대수 기초

로봇을 "수학으로 다루는" 첫걸음. 로봇의 3요소(센서·액추에이터·제어기)와 동작 루프를 잡고, 모든 로봇 수학의 출발점인 좌표계·강체 변환으로 들어갑니다. numpy로 벡터·행렬을 다루고, 회전행렬 SO(2)/SO(3)과 동차변환행렬 SE(3)로 "한 좌표계의 점을 다른 좌표계로 옮기는" 핵심 도구를 손에 익힙니다. (모든 Python 예제는 numpy로 실제 실행·검증했습니다.)

1. 로봇이란? — 센서 · 액추에이터 · 제어기와 Sense-Plan-Act

로봇은 "환경을 감지(Sense)하고, 무엇을 할지 계획(Plan)하고, 실제로 움직여 행동(Act)하는" 기계입니다. 이 순환을 가능하게 하는 하드웨어는 크게 세 가지로 나뉩니다.

💡 비유로 이해하기: 로봇 = 사람의 감각 · 근육 · 뇌

센서는 눈·귀·피부(감각기관)로 바깥세상의 정보를 들여오고, 액추에이터(모터)는 근육처럼 실제로 몸을 움직이며, 제어기(컴퓨터)는 뇌가 되어 "지금 들어온 정보로 무엇을 할지" 결정합니다. 로봇 공부는 결국 이 세 기관이 좌표(숫자)로 대화하게 만드는 일입니다.

👁️ 센서 (Sense)

IMU(자세·가속), 엔코더(바퀴·관절 회전량), LiDAR(거리·지도), 카메라(영상), 초음파(근거리 장애물). "지금 세상이 어떤지"를 숫자로 바꾼다.

💪 액추에이터 (Act)

DC 모터(연속 회전), 서보 모터(목표 각도 유지), 스텝 모터(정밀 각도 분할). 전기 신호를 실제 운동으로 바꾼다.

🧠 제어기 (Plan)

MCU(아두이노 등 실시간 저수준) + SBC(라즈베리파이·젯슨 등 고수준 연산). 센서값으로 다음 행동을 계산한다.

로봇의 분류와 자유도(DOF)

형태에 따라 로봇은 크게 나뉩니다. 매니퓰레이터(고정된 로봇팔 — 공장 용접·조립), 모바일 로봇(스스로 이동 — AMR·AGV·자율주행), 휴머노이드/레그드 로봇(다리로 걷는 로봇). 이들을 수학적으로 다룰 때 핵심 개념이 자유도(DOF, Degrees of Freedom)입니다. 3차원 공간의 강체(rigid body) 하나는 6 자유도를 가집니다 — 위치 3개(x, y, z) + 자세(방향) 3개(roll·pitch·yaw). 로봇팔이 "6축"이라는 말은 임의의 위치·자세에 도달하기 위해 보통 6개의 관절(DOF)이 필요하기 때문입니다.

📐 자유도(DOF) 정리

• 평면(2D) 강체 = 3 DOF (x, y, 방향 θ)
• 공간(3D) 강체 = 6 DOF (위치 x·y·z + 자세 roll·pitch·yaw)
• 차동구동 모바일 로봇은 바퀴 2개로 평면 위 3 DOF 중 일부만 직접 제어합니다(R4에서 다룸).

2. 좌표계와 강체 — 모든 로봇 수학의 출발점

"로봇이 어디 있나?"라는 질문엔 항상 "무엇을 기준으로?"가 따라옵니다. 그 기준이 바로 좌표계(프레임, frame)입니다. 로봇 시스템에는 여러 프레임이 공존합니다 — 방 전체의 기준인 월드(world) 프레임, 로봇 몸체에 붙은 베이스(base_link) 프레임, 카메라·LiDAR마다 붙은 센서 프레임. 같은 점이라도 어느 프레임에서 보느냐에 따라 좌표가 달라집니다.

💡 비유로 이해하기: 지도와 "현재 위치 + 바라보는 방향"

내비게이션을 켜면 화면엔 두 가지가 있습니다 — 도시 전체 지도(월드 프레임)와, 그 위에서 "내가 선 자리 + 내가 향한 방향"을 나타내는 화살표(바디 프레임). 앞으로 1m 가라는 명령은 바디 프레임 기준("내 코앞")이지만, 지도에 점을 찍으려면 월드 프레임 좌표로 바꿔야 합니다. 이 "프레임 사이 좌표 변환"이 로보틱스의 가장 기본 연산입니다.

좌표축을 잡는 방식은 약속이 필요합니다. 로보틱스는 거의 항상 오른손 좌표계(right-handed)를 씁니다. 오른손 엄지(x)·검지(y)·중지(z)를 서로 직각으로 펴면 x→y→z의 방향이 정해집니다. 특히 ROS 생태계의 표준 규약 REP 103은 로봇 바디 프레임을 다음과 같이 고정합니다.

x — 전방(forward)

로봇이 바라보는 정면 방향.

y — 좌측(left)

정면을 봤을 때 왼쪽.

z — 상방(up)

하늘 방향. (x→y→z 오른손)

정리하면, "로봇의 자세(pose)"란 한 프레임이 다른 프레임에 대해 얼마나 이동(translation)하고 얼마나 회전(rotation)했는가입니다. 이동은 벡터로, 회전은 회전행렬로 표현합니다 — 이제 그 도구들을 numpy로 만나봅니다.

3. numpy로 벡터 · 행렬 다루기

로보틱스의 위치·방향·속도는 모두 벡터이고, 변환은 모두 행렬입니다. 파이썬에서는 numpy가 이 둘을 빠르고 간결하게 다룹니다. 가장 자주 쓰는 연산 네 가지부터 손에 익힙니다.

💡 비유로 이해하기: 벡터 = "크기와 방향을 가진 화살표"

속도 "북동쪽으로 시속 5km"는 숫자 하나로 못 적습니다. 방향과 크기가 함께 있어야 하죠 — 그게 벡터(화살표)입니다. 두 화살표의 내적(dot)은 "얼마나 같은 방향인지", 외적(cross)은 "두 화살표가 만드는 평면의 수직 방향(회전축)"을, 노름(norm)은 "화살표의 길이(크기)"를 알려줍니다.

numpy 벡터 기초 — 거리 · 각도 · 외적 
import numpy as np

# 두 점 (로봇 위치 A, 목표 B) — 2D, 단위: 미터
A = np.array([1.0, 2.0])
B = np.array([4.0, 6.0])

# 1) 변위 벡터와 거리(유클리드 노름)
d = B - A
dist = np.linalg.norm(d)              # sqrt(3^2 + 4^2) = 5.0
print("변위:", d, "거리:", dist)

# 2) 두 방향 벡터 사이의 각도
u = np.array([1.0, 0.0])              # 로봇이 바라보는 방향(+x)
v = np.array([0.0, 1.0])              # 목표 방향(+y)
cos_t = np.dot(u, v) / (np.linalg.norm(u) * np.linalg.norm(v))
angle = np.degrees(np.arccos(cos_t))
print("사이 각도(도):", angle)         # 90.0

# 3) 3D 외적 — 회전축/법선 구하기 (오른손 법칙)
ux = np.array([1.0, 0.0, 0.0])
uy = np.array([0.0, 1.0, 0.0])
print("x × y =", np.cross(ux, uy))    # [0 0 1] (= z축)

✅ 실행 결과 (검증됨)

변위: [3. 4.] 거리: 5.0
사이 각도(도): 90.0
x × y = [0. 0. 1.]

핵심 API를 표로 정리합니다. (행렬곱은 @ 연산자가 가장 명확합니다.)

연산numpy로보틱스에서의 쓰임
내적 (dot)np.dot(u, v) · u @ v두 벡터의 정렬도, 투영, 각도 계산
외적 (cross)np.cross(u, v)회전축·법선 벡터(3D), 오른손 법칙
크기 (norm)np.linalg.norm(v)거리, 속력, 벡터 길이
행렬곱A @ B회전·변환 적용 및 합성

4. 회전행렬 — 방향을 숫자로 (SO(2) · SO(3))

점이나 벡터를 원점 기준으로 돌리는 도구가 회전행렬입니다. 2차원에서 각도 θ만큼 반시계로 회전하는 행렬은 다음과 같습니다.

R(θ) = [ [ cos θ, −sin θ ], [ sin θ, cos θ ] ]   →   p′ = R(θ) · p

💡 비유로 이해하기: 회전행렬 = "나침반 다이얼"

회전행렬은 좌표를 입력하면 "θ만큼 돌린 좌표"를 내놓는 다이얼입니다. 중요한 성질이 있습니다 — 다이얼을 돌렸다 정확히 반대로 돌리면 제자리(역행렬 = 전치)이고, 돌려도 화살표의 길이는 변하지 않습니다(거리 보존). 그래서 회전행렬은 늘 "반듯한(직교) 행렬"입니다.

2D 회전행렬과 그 핵심 성질 
import numpy as np

def rot2d(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[c, -s],
                     [s,  c]])

R = rot2d(np.radians(90))            # +90도(반시계) 회전
p = np.array([1.0, 0.0])            # +x 위의 점
p2 = R @ p                          # 회전 적용
print("회전된 점:", np.round(p2, 3))  # [0, 1]  (+x → +y)

# 회전행렬의 핵심 성질 3가지
print("직교성 R·Rᵀ = I:\n", np.round(R @ R.T, 6))
print("행렬식 det(R) =", round(float(np.linalg.det(R)), 6))   # +1.0
print("역행렬 == 전치?", np.allclose(np.linalg.inv(R), R.T))   # True

✅ 실행 결과 (검증됨)

회전된 점: [0. 1.]
직교성 R·Rᵀ = I:
 [[1. 0.]
 [0. 1.]]
행렬식 det(R) = 1.0
역행렬 == 전치? True

이 성질들이 회전행렬을 정의합니다. 이런 행렬들의 모임을 SO(2)(2D), SO(3)(3D)라고 부릅니다 — Special Orthogonal group.

  • 직교(orthonormal): R · Rᵀ = I — 행/열이 서로 수직인 단위벡터.
  • det(R) = +1: 거울처럼 뒤집지 않고 "순수 회전"만 한다(−1이면 반사가 섞임).
  • 역행렬 = 전치: R−¹ = Rᵀ — 역회전을 구하기가 공짜.

3차원에서는 각 축을 기준으로 도는 기본 회전 Rx, Ry, Rz가 있고, 이들을 곱해 임의의 3D 회전을 만듭니다. 단, 회전 합성은 순서가 중요합니다(비가환) — Rx·Rz ≠ Rz·Rx. "x로 돌고 z로 돌기"와 "z로 돌고 x로 돌기"는 결과가 다릅니다.

⚠️ 면접 포인트: 오일러각과 짐벌락(Gimbal Lock)

3D 자세를 roll·pitch·yaw 세 각도(오일러각)로 적으면 직관적이지만, 특정 자세에서 두 축이 겹쳐 한 자유도를 잃는 짐벌락이 생깁니다. 그래서 실무에서는 회전행렬이나 쿼터니언(quaternion)으로 자세를 저장합니다(쿼터니언은 이후 챕터에서). 핵심: "오일러각은 사람이 읽기 좋고, 회전행렬·쿼터니언은 계산이 안전하다."

5. 동차변환행렬 SE(3) — 회전 + 이동을 한 번에

현실의 프레임 변환은 "회전만" 또는 "이동만"이 아니라 회전과 이동이 함께 일어납니다. 이 둘을 하나의 4×4 행렬로 묶은 것이 동차변환행렬(Homogeneous Transformation Matrix)이고, 이런 행렬들의 모임을 SE(3)(Special Euclidean group)라고 부릅니다. (SE(3)는 1절의 6자유도 — 회전 3 + 이동 3 — 를 그대로 담으며, 회전만 다루는 SO(3)는 3자유도입니다.)

T = [ [ R (3×3 회전),   t (3×1 이동) ], [ 0  0  0,   1 ] ]   (4×4)

💡 비유로 이해하기: SE(3) = "주소 변환 도장" 하나

"{B} 프레임 좌표"를 "{W} 프레임 좌표"로 바꾸려면 원래는 ① 회전하고 ② 이동하는 두 단계가 필요합니다. 동차변환행렬은 이 두 단계를 도장 하나(행렬 한 번 곱)로 찍어 줍니다. 비결은 점에 1을 하나 덧붙이는 것(동차좌표) — (x, y, z) → (x, y, z, 1). 이 1 덕분에 "곱셈(회전)"과 "덧셈(이동)"을 한 번의 행렬곱으로 합칠 수 있습니다.

여러 프레임은 변환을 곱으로 이어 붙여(chaining) 연결합니다. "월드→베이스" 변환 T_w_b와 "베이스→센서" 변환 T_b_c가 있으면, "월드→센서"는 그냥 T_w_b @ T_b_c입니다.

SE(3) 만들기 · 프레임 합성 · 점 변환 
import numpy as np

def rot_z(theta):
    c, s = np.cos(theta), np.sin(theta)
    return np.array([[c, -s, 0],
                     [s,  c, 0],
                     [0,  0, 1]])

def make_T(R, t):
    """3x3 회전 R + 3D 평행이동 t  →  4x4 동차변환행렬 SE(3)."""
    T = np.eye(4)
    T[:3, :3] = R
    T[:3, 3] = t
    return T

# 월드(W)에서 본 로봇 베이스(B): +z로 90도 돌고 (2,0,0)에 위치
T_w_b = make_T(rot_z(np.radians(90)), np.array([2.0, 0.0, 0.0]))

# 베이스(B)에서 본 센서(C): 평행이동 (1,0,0), 회전 없음
T_b_c = make_T(np.eye(3), np.array([1.0, 0.0, 0.0]))

# 프레임 합성: 월드에서 본 센서
T_w_c = T_w_b @ T_b_c
print("센서의 월드 위치:", np.round(T_w_c[:3, 3], 3))  # (2, 1, 0)

# 센서 좌표 (0.5, 0, 0)인 점을 월드 좌표로 변환 (동차좌표: 끝에 1)
p_c = np.array([0.5, 0.0, 0.0, 1.0])
p_w = T_w_c @ p_c
print("점의 월드 좌표:", np.round(p_w[:3], 3))         # (2, 1.5, 0)

✅ 실행 결과 (검증됨)

센서의 월드 위치: [2. 1. 0.]
점의 월드 좌표: [2.  1.5 0. ]

표기 관습 하나만 익히면 평생 편합니다. T_w_b(또는 TWB)는 "베이스 프레임 {B}를 월드 프레임 {W}에서 본 자세"이자, 동시에 "{B} 좌표를 {W} 좌표로 바꾸는 변환"입니다. 그래서 p_w = T_w_b @ p_b처럼 아래첨자가 점의 프레임과 맞물리게 곱하면 됩니다. (표기 관습은 문헌마다 조금씩 다릅니다 — 여기서는 "아래첨자 안쪽이 약분되듯 맞물린다"는 규칙으로 통일합니다.)

6. 역변환 — 반대 방향으로 좌표 되돌리기

"{B}→{W}" 변환을 알면 그 반대 "{W}→{B}"도 필요합니다. 일반 행렬은 np.linalg.inv로 역행렬을 구하지만, SE(3)는 구조를 이용한 공식으로 더 빠르고 수치적으로 안정적으로 역변환을 만들 수 있습니다.

T−¹ = [ [ Rᵀ,   −Rᵀ·t ], [ 0  0  0,   1 ] ]

💡 비유로 이해하기: 역변환 = "왔던 길 그대로 되짚기"

회전을 되돌리는 건 공짜입니다(전치 Rᵀ). 하지만 이동을 되돌릴 때는 주의해야 합니다 — 먼저 방향(회전)을 되돌린 다음 그 방향에서 이동을 빼야 하므로 −Rᵀ·t가 됩니다. 단순히 −t가 아니라는 점이 핵심입니다.

SE(3) 역변환과 검증 (T · T⁻¹ = I) 
import numpy as np
# (5절의 make_T, rot_z, T_w_c 를 그대로 이어서 사용한다고 가정)

def invert_T(T):
    """SE(3) 역변환: [[R, t],[0,1]]⁻¹ = [[Rᵀ, -Rᵀt],[0,1]]."""
    R = T[:3, :3]
    t = T[:3, 3]
    Tinv = np.eye(4)
    Tinv[:3, :3] = R.T
    Tinv[:3, 3] = -R.T @ t
    return Tinv

T_c_w = invert_T(T_w_c)              # 센서에서 본 월드
print("T_w_c · T_c_w = I ?", np.allclose(T_w_c @ T_c_w, np.eye(4)))      # True

# 구조적 역변환이 일반 역행렬과 같은지 확인 (단, 구조식이 더 빠르고 안정적)
print("구조적 역 == np.linalg.inv ?", np.allclose(T_c_w, np.linalg.inv(T_w_c)))  # True

✅ 실행 결과 (검증됨)

T_w_c · T_c_w = I ? True
구조적 역 == np.linalg.inv ? True

이로써 R1의 핵심 도구 상자가 완성됐습니다 — 벡터·행렬, 회전행렬(SO), 동차변환(SE)과 그 역변환. 다음 챕터부터는 이 좌표 도구 위에 센서(R2)·제어(R5)·ROS 2(R6)를 쌓아 올립니다.
