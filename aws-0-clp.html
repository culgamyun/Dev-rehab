AWS 자격증 > A0. CLP

A0. CLP — 클라우드 기초

AWS 자격증 트랙의 출발점입니다. 클라우드가 무엇이고 왜 쓰는지부터 글로벌 인프라(리전·AZ), 공동 책임 모델, IAM, 핵심 서비스 지도, 요금·지원까지 — 비전공·공백기 복귀자도 그림과 비유로 한 번에 잡도록 정리했습니다. 자격증으로는 AWS Certified Cloud Practitioner(CLF-C02, 2026 기준)의 네 도메인 전체를 폭넓게 다지며, 특히 비중이 큰 '클라우드 기술과 서비스(34%)'와 '보안과 규정 준수(30%)'에 무게를 둡니다.

1. 클라우드란 무엇인가 — 빌려 쓰는 IT

클라우드 컴퓨팅은 서버·스토리지·데이터베이스·네트워크 같은 IT 자원을 직접 사다 두지 않고, 인터넷으로 필요한 만큼 빌려 쓰고 쓴 만큼 내는 방식입니다. 예전(온프레미스)에는 서비스를 시작하려면 서버를 구매하고, 전산실을 마련하고, 전기·냉방·보안까지 직접 챙겨야 했습니다. 클라우드에서는 이 모든 것을 AWS가 운영하고, 우리는 콘솔이나 코드로 몇 분 만에 자원을 켜고 끕니다.

💡 비유로 이해하기: 발전소 vs 콘센트

공장을 돌리려고 자가 발전소를 짓는 것이 온프레미스입니다 — 큰 선투자, 남으면 낭비, 모자라면 정전. 반면 벽의 콘센트에 플러그를 꽂고 쓴 만큼 전기료를 내는 것이 클라우드입니다. 더 필요하면 코드를 더 꽂고, 안 쓰면 뽑으면 됩니다. "내 발전소"를 소유하는 대신 "전력망"을 빌려 쓰는 셈이죠.

AWS가 말하는 클라우드의 6가지 장점은 시험에 자주 그대로 나오니 키워드로 외워 두세요.

장점한 줄 의미
선투자 → 사용량 기반 비용큰돈을 미리 묶지(CapEx) 않고, 쓴 만큼만(OpEx) 낸다.
규모의 경제수백만 고객이 함께 쓰므로 AWS의 대량 구매 단가가 요금에 반영된다.
용량 예측 불필요(탄력성)모자라거나 남는 추측 없이, 수요에 맞춰 자동으로 늘리고 줄인다.
속도와 민첩성서버 도착을 몇 주 기다리지 않고, 몇 분 만에 자원을 띄운다.
데이터센터 운영 탈피전산실·전력·냉방·물리보안 운영에서 손을 뗀다(차별화에 집중).
몇 분 만의 글로벌 확장전 세계 리전에 클릭 몇 번으로 서비스를 펼친다.

✅ 핵심 정리

'탄력성(Elasticity)'은 수요에 맞춰 자동으로 키우고 줄이는 능력이고, '민첩성(Agility)'은 새 자원을 빠르게 띄우는 속도입니다. 시나리오 문제에서 '트래픽이 출렁인다 → 탄력성', '아이디어를 빨리 실험한다 → 민첩성'으로 매칭하세요.

2. AWS 글로벌 인프라 — 리전 · AZ · 엣지

AWS의 물리적 토대는 세 층으로 이해하면 됩니다. 리전(Region)은 서울·도쿄·버지니아처럼 지리적으로 떨어진 거대한 데이터센터 권역입니다. 각 리전 안에는 가용영역(AZ, Availability Zone)이 둘 이상(대개 3개 이상) 있는데, AZ는 전력·냉방·네트워크가 서로 독립된, 물리적으로 분리된 데이터센터 묶음입니다. 리전 바깥에는 사용자 가까이에 콘텐츠를 캐싱하는 엣지 로케이션(Edge Location)이 전 세계에 깔려 있습니다(CloudFront가 사용).

💡 비유로 이해하기: 도시 · 건물 · 동네 편의점

리전은 하나의 '도시', AZ는 그 도시 안의 서로 떨어진 '건물'들, 엣지 로케이션은 사용자 동네마다 있는 '편의점'입니다. 한 건물(AZ)에 정전이 나도 다른 건물이 멀쩡하면 영업은 계속됩니다. 그리고 자주 찾는 물건(정적 콘텐츠)은 멀리 본점까지 가지 않고 동네 편의점(엣지)에서 바로 집어 옵니다.

구분무엇인가핵심 포인트
리전 (Region)지리적으로 분리된 데이터센터 권역리전마다 자원·요금·서비스 가용성이 다를 수 있다. 규정/지연시간 고려해 선택.
가용영역 (AZ)리전 내 물리적으로 분리된 DC 묶음(보통 3개 이상)다중 AZ 배포 = 고가용성의 기본. 한 AZ 장애가 전체로 번지지 않음.
엣지 로케이션사용자 근처의 콘텐츠 캐싱 거점CloudFront(CDN)·일부 글로벌 서비스가 사용. 지연시간 단축.

📝 시험에 이렇게 나온다

"한 AZ 장애에도 살아남는 가용성" → 답은 다중 AZ(Multi-AZ) 배포. "특정 국가 규정상 데이터를 그 나라에 둬야 한다" → 리전 선택(데이터 상주). "전 세계 사용자에게 정적 콘텐츠를 빠르게" → 엣지 로케이션 / CloudFront. 셋의 역할을 섞지 마세요.

3. 공동 책임 모델 — 누가 무엇을 지키나

클라우드 보안은 AWS와 고객이 나눠서 책임집니다. AWS는 "클라우드의 보안(Security of the Cloud)" — 데이터센터 물리보안, 하드웨어, 가상화(하이퍼바이저), 기반 네트워크를 책임집니다. 고객은 "클라우드 안에서의 보안(Security in the Cloud)" — OS 패치, 방화벽(보안 그룹) 설정, IAM 권한, 데이터 암호화, 애플리케이션을 책임집니다.

💡 비유로 이해하기: 아파트 임대

건물 골조·외벽·공용 출입통제·소방 시스템은 건물주(AWS)가 책임집니다. 하지만 내 집 현관문을 잠그고(방화벽), 누구에게 열쇠를 줄지 정하고(IAM), 귀중품을 금고에 넣는(암호화) 것은 입주자(고객) 몫입니다. 건물이 아무리 튼튼해도 내가 현관문을 열어 두면(보안 그룹 0.0.0.0/0 개방) 사고가 납니다.

중요한 건, 경계가 서비스 유형에 따라 이동한다는 점입니다. EC2(IaaS)처럼 직접 관리하는 자원은 OS 패치까지 고객이 지지만, RDS·Lambda·S3 같은 관리형 서비스로 갈수록 AWS가 더 많이 떠안고 고객 책임은 줄어듭니다.

항목EC2 (직접 관리)RDS / Lambda (관리형)
물리 인프라·하이퍼바이저AWSAWS
게스트 OS 패치고객AWS (관리형이라 대신 처리)
방화벽 / 네트워크 접근 제어고객 (보안 그룹)고객 (접근 정책)
IAM 권한·데이터 암호화 설정고객고객
내 데이터 자체고객고객

⚠️ 함정 주의

데이터·IAM·암호화 설정·네트워크 접근 제어는 어떤 서비스에서도 '항상 고객 책임'입니다. "S3에 객체를 넣었으니 보안은 AWS가 알아서 한다"는 틀린 생각 — 버킷을 퍼블릭으로 열어 데이터가 유출되면 그건 고객 책임입니다.

4. IAM 첫걸음 — 계정 보안의 출발

IAM(Identity and Access Management)은 "누가(Authentication) 무엇을 할 수 있는가(Authorization)"를 다루는 AWS의 권한 관리 서비스입니다. IAM 자체는 추가 비용이 없는 전역(global) 서비스입니다. 핵심 구성 요소 네 가지를 구분하세요.

구성 요소무엇인가비유
사용자 (User)사람/앱에 대응하는 영구 신원(로그인·키 보유)직원 개인 사원증
그룹 (Group)사용자 묶음. 권한을 한꺼번에 부여'개발팀' 같은 부서
역할 (Role)영구 키 없이 임시 자격증명을 발급받아 '빌려 쓰는' 신원방문증(필요할 때만 발급)
정책 (Policy)권한을 정의한 JSON 문서(허용/거부)출입 규칙서

역할(Role)이 특히 중요합니다. EC2·Lambda 같은 AWS 자원이 다른 자원(예: S3)에 접근할 때, 키를 코드에 박아 두는 대신 역할을 연결하면 임시 자격증명이 자동 발급·회전되어 키 유출 위험이 사라집니다.

IAM 정책 예시 — 특정 S3 버킷 읽기만 허용(최소 권한)
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::my-app-bucket",
        "arn:aws:s3:::my-app-bucket/*"
      ]
    }
  ]
}

✅ 핵심 정리: 루트 보호 4계명

① 루트(root) 사용자에 MFA(다단계 인증)를 켠다. ② 일상 작업은 루트가 아니라 최소 권한 IAM 사용자/역할로 한다. ③ 루트 액세스 키는 만들지 않는다(AWS 강력 비권장). ④ '필요한 권한만 준다'는 최소 권한 원칙(Least Privilege)을 모든 정책에 적용한다.

5. 핵심 서비스 한 장 지도

AWS 서비스는 수백 개지만, CLP는 "이 일에는 어떤 카테고리의 서비스를 쓰는가"를 묻습니다. 컴퓨트·스토리지·데이터베이스·네트워킹 네 기둥의 대표 서비스만 먼저 또렷이 잡으면 절반은 끝납니다.

카테고리대표 서비스한 줄 용도
컴퓨트Amazon EC2직접 관리하는 가상 서버(OS·확장·패치 제어). 범용 워크로드.
AWS Lambda서버 없는 함수 실행. 이벤트가 올 때만 돌고 실행 시간만큼 과금.
스토리지Amazon S3무한 확장 객체 스토리지(파일·백업·정적 웹·데이터 레이크).
Amazon EBSEC2에 붙이는 블록 디스크(범용 기본 권장: gp3).
데이터베이스Amazon RDS관리형 관계형 DB(MySQL·PostgreSQL 등). 패치·백업·복제 자동.
Amazon DynamoDB완전관리형 서버리스 NoSQL(키-값). 대규모·저지연.
네트워킹Amazon VPC내 전용 가상 네트워크(서브넷·라우팅·방화벽 경계).
Amazon CloudFront엣지 기반 CDN. 콘텐츠를 사용자 가까이서 캐싱·전송.

📝 시험에 이렇게 나온다

"OS까지 내 맘대로 제어" → EC2. "서버 관리 없이 이벤트로만 실행" → Lambda. "대용량 파일·정적 웹 호스팅" → S3. "관계형 DB를 관리 부담 없이" → RDS. "전 세계 콘텐츠 가속" → CloudFront. CLP는 '깊이'가 아니라 '어떤 서비스가 그 일을 하나'를 묻습니다.

6. 요금과 지원 — 종량제 · 프리티어 · 지원 플랜

AWS의 기본 과금 철학은 종량제(Pay-as-you-go) — 약정 없이 쓴 만큼 냅니다. 비용을 보고·관리하는 도구와, 처음에 무료로 실습할 수 있는 프리티어, 그리고 지원 플랜을 알아 두면 '청구·가격·지원' 도메인(12%)이 정리됩니다.

AWS 프리티어(Free Tier) 3종을 구분하세요.

프리티어 종류의미예시 느낌
12개월 무료가입 후 1년간 일정 한도까지 무료EC2 마이크로 인스턴스 일정 시간 등
상시 무료(Always Free)기간 제한 없이 매월 한도까지 무료Lambda 월 요청·실행 시간 한도 등
체험(Trials)특정 서비스 활성화 시점부터 단기간 무료일부 서비스 단기 평가판

비용 관리 도구: Billing(청구 대시보드)로 현재 청구를 보고, Cost Explorer로 지출 추이를 시각화·분석하며, AWS Budgets로 예산 한도를 걸고 초과(예측) 시 알림을 받습니다. 배포 전 견적은 Pricing Calculator로 뽑습니다.
