순서와 분류로
외우는 영역

SW공학 약술은 "순서를 묻는 문제"(결합도·응집도 단계)와 "분류를 묻는 문제"(디자인패턴, 테스트, UML)가 핵심입니다. 두문자와 분류 체계만 잡으면 단답으로 확실히 가져갈 수 있습니다.

단답·약술 빈출 ★★★ 디자인패턴 · 모듈화 핵심 용어 35+ 암기카드 24 문제 16
✓ 이 영역의 공략법 SW공학은 순서 문제(결합도 약→강, 응집도 강→약)와 분류 문제(패턴 3종, 테스트 2종)가 반복됩니다. 순서는 두문자로, 분류는 "어느 그룹에 속하는가"로 외우세요. LOC 기반 개발기간 계산도 공식만 알면 득점입니다.
01

모듈화 — 결합도 · 응집도

SW공학 최대 빈출. "결합도는 약하게, 응집도는 강하게"가 좋은 모듈화의 핵심 원칙입니다.

CORE

모듈 독립성의 원칙

★★★

모듈의 독립성을 높이려면 결합도(Coupling)는 낮게, 응집도(Cohesion)는 높게 만들어야 합니다.

  • 결합도 — 모듈과 모듈 사이의 상호 의존 정도 (낮을수록 좋음)
  • 응집도 — 모듈 내부 구성요소의 기능적 집중 정도 (높을수록 좋음)
⚠ 단골 빈칸: "모듈 독립성을 높이려면 ( )는 약하게, ( )는 강하게" → 답: 결합도, 응집도. 순서 바꾸지 말 것.
COUPLING

결합도 6단계 (약 → 강)

★★★
◀ 약함 (좋은 품질)강함 (낮은 품질) ▶
1자료 결합도파라미터로 데이터만 전달 (Data)
2스탬프 결합도배열·구조체 등 자료구조 전달 (Stamp)
3제어 결합도제어 신호(플래그)를 전달 (Control)
4외부 결합도외부 전역 변수를 참조 (External)
5공통 결합도전역 데이터를 공유 (Common)
6내용 결합도다른 모듈 내부를 직접 참조 (Content)
🔑 자·스·제·외·공·내 (자료→스탬프→제어→외부→공통→내용). 위로 갈수록 좋은 결합. 순서 묻는 문제 단골.
COHESION

응집도 7단계 (강 → 약)

★★★
◀ 강함 (좋은 품질)약함 (낮은 품질) ▶
1기능적단일 기능 수행 (Functional)
2순차적출력이 다음 입력으로 (Sequential)
3교환(통신)적동일 입출력 데이터 사용 (Communication)
4절차적순서대로 실행 (Procedural)
5시간적특정 시점에 함께 실행 (Temporal)
6논리적유사 성격끼리 묶음 (Logical)
7우연적서로 관련 없음 (Coincidental)
🔑 기·순·교·절·시·논·우 (기능적이 최고, 우연적이 최악). "관련 없는 요소들" = 우연적 응집도.
02

비용 산정 — LOC

계산 문제로 출제. 공식만 알면 확실한 득점원입니다.

CALC

LOC 기반 개발 기간 산정

★★☆

LOC(Line Of Code) 기법: 총 라인 수를 인력·생산성으로 나눠 기간을 구합니다.

●●●loc.calc
개발 기간 = 총 LOC ÷ (투입 인원 × 1인당 월 생산성)

# 예: LOC 30000, 개발자 5명, 1인당 월 300라인
30000 ÷ (5 × 300) = 30000 ÷ 1500 = 20개월

노력(인월) = 개발 기간 × 투입 인원
생산성 = 총 LOC ÷ 노력(인월)
🧮 계산식을 반드시 쓰세요. 답만 쓰면 감점될 수 있습니다. 단위(개월, 인월)도 정확히.
03

테스트 — 화이트박스 vs 블랙박스

테스트 기법 분류가 핵심. 내부 구조를 보느냐(화이트) 안 보느냐(블랙)로 구분.

TEST

화이트박스 vs 블랙박스

★★★
화이트박스내부 구조·코드를 보고 테스트 (구조 기반). 종류: 기초 경로, 조건/분기, 루프 검사
블랙박스내부를 모르고 입출력으로 테스트 (명세 기반). 종류: 동치 분할, 경계값 분석, 원인-결과
⚠ 핵심: 화이트박스="투명해서 안이 보임"(코드 기반), 블랙박스="검은 상자, 안 안 보임"(명세 기반). 경계값 분석은 블랙박스 단골.
LEVEL

테스트 단계 (V-모델)

★★☆
  • 단위 테스트 — 모듈 하나 단위 검증
  • 통합 테스트 — 모듈 간 인터페이스 검증 (상향식/하향식)
  • 시스템 테스트 — 전체 시스템 요구사항 검증
  • 인수 테스트 — 사용자 관점 최종 검증 (알파/베타)
📊 통합 방식: 하향식(Top-down)은 스텁(Stub) 사용, 상향식(Bottom-up)은 드라이버(Driver) 사용.
04

UML 다이어그램

정적(구조적)/동적(행위적) 분류와 대표 다이어그램이 출제됩니다.

UML

구조적 vs 행위적 다이어그램

★★☆
구조적(정적)클래스, 객체, 컴포넌트, 배치, 패키지 다이어그램
행위적(동적)유스케이스, 시퀀스, 상태, 활동, 커뮤니케이션 다이어그램

접근 제어자 표기 (클래스 다이어그램)

  • + public (외부 접근 허용) / - private (내부만)
  • # protected (파생 클래스) / ~ default (동일 패키지)
🔗 관계: 연관, 집합(약한 포함), 복합(강한 포함), 일반화(상속), 의존, 실체화(인터페이스 구현).
05

개발 방법론 · 프로세스

전통 모델과 애자일의 특징, 차이가 단답·약술로 출제됩니다.

SDLC

소프트웨어 개발 모델

★★☆
폭포수단계를 순차적으로 진행 (Waterfall). 가장 고전적
프로토타입시제품을 만들어 요구사항 확인
나선형위험 분석 중심, 반복적 (Spiral). 대규모에 적합
애자일반복·점진적, 변화 수용. 스크럼, XP가 대표
🏃 애자일 기법: 스크럼(스프린트, 데일리 미팅) / XP(페어 프로그래밍, TDD). 애자일 선언 4가지 가치도 출제.
PRINCIPLE

객체지향 설계 원칙 (SOLID)

★★☆
SRP단일 책임 — 클래스는 하나의 책임만
OCP개방-폐쇄 — 확장엔 열림, 수정엔 닫힘
LSP리스코프 치환 — 자식이 부모를 대체 가능
ISP인터페이스 분리 — 필요한 것만 의존
DIP의존 역전 — 추상에 의존, 구체에 의존 X
🔑 S·O·L·I·D. 특히 OCP(개방-폐쇄)가 단답으로 자주 나옵니다.

GoF 디자인패턴 분류

GoF(Gang of Four)가 제안한 23개 패턴. 시험은 "어느 분류에 속하는가"를 묻습니다. 탭을 눌러 생성·구조·행위 패턴을 확인하세요.

🔑 3대 분류: 생성(Creational) = 객체 생성 / 구조(Structural) = 객체 조합·구조 / 행위(Behavioral) = 객체 간 책임·상호작용.
